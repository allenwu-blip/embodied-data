# v0.3.x patch backlog

Carried-forward items from `v0.2.x-patches.md` that didn't ship in v0.3.0,
plus new candidates surfaced during v0.3.0 video work. Each entry includes
a one-liner description, a reproduction (where applicable), the proposed
fix, and a v0.4-or-later note if the underlying gap is bigger than
"patch".

---

## [0.3.1?] multi-camera support (fisheye / hand / back)

**Symptom**

v0.3.0 ingests `head_color.mp4` only. Beta upstream packages 7 cameras
per episode (`head_color`, `fisheye_left`, `fisheye_right`, `hand_left`,
`hand_right`, `back_left`, `back_right`). Labs running multi-view VLA
training currently get only the head view.

**Proposed fix**

Generalize `find_head_color_video` → `find_camera_videos(ep_dir) ->
dict[str, Path]` returning every present camera. Each becomes its own
`observation.images.<key>` feature with its own re-encoded mp4 directory.
Re-use the same h264/bf=0/g=2 contract per camera. No batch model change
— each camera is an additional all-or-nothing gate.

**Severity**

MEDIUM. Cameras absent → models trained on v0.3.0 data have a head-only
input, which is fine for tasks like "Insert the straw" but limiting for
bimanual policies.

## [0.3.2?] sparse `action/*/index` companions surface as `auxiliary.*.mask`

**Symptom**

Beta action subgroups carry `index` arrays sized differently from frame
count (e.g., `action/joint/index` 1046 vs 1090 frames). Per upstream
README these mark "when the control source is actually sending signals" —
sparse mask metadata. v0.3.0 drops these silently.

**Proposed fix**

Surface as `auxiliary.<group>.mask` features with frame-aligned
1090-length boolean arrays. No LeRobot v3 spec slot for this, so use
`auxiliary.*` prefix to signal it's an extension column.

**Severity**

LOW for most VLA pipelines (which read `action` directly). MEDIUM for
imitation-learning pipelines that care about which timesteps had
real teleoperator input.

## [0.3.3?] `state/end/*` end-pose flattening (32-dim)

**Symptom**

Beta `state/end/{position,orientation,velocity,wrench,angular}` is
discarded by v0.3.0 — only the 20-dim joint-space proprio is captured.
Lab teams asking for end-effector pose targets (a common RL/IL feature)
get nothing from this column.

**Proposed fix**

Add `observation.state.end_pose` as a 32-dim float32 feature
(2 hands × {3 pos, 4 quat, 3 vel, 3 wrench, 3 angular} = 16 each =
32 total). Optional opt-in via convert flag, since most LeRobot v3
consumers only read 20-dim.

**Severity**

LOW today (no user request yet). MEDIUM if a user pipeline actually
needs Cartesian end-effector targets.

## [0.3.x?] reverse `lerobot-v3 → agibot-beta`

**Symptom**

`embodied_data.convert.lerobot_to_agibot` exists for sim DigitalWorld
only. Beta has no reverse path — labs that produce LeRobot v3 datasets
and want to compare against Beta layout can't.

**Proposed fix**

Mirror `lerobot_to_agibot.py` for Beta: 20-dim observation.state →
`state/{joint, effector, head, waist}` h5, action → first-difference
inverse, video re-mux to upstream codec (av1 or copy-passthrough).

**Severity**

LOW. No user has asked for this yet, but it's the symmetric completion
of the v0.3 forward path.
