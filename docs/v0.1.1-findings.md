# v0.1.1 findings — embodied-data v0.1.0 vs real-world AgiBot Beta

**Source**: `agibot-world/AgiBotWorld-Beta` task 675 episode 936938 ("Insert
the straw"), 1090 frames @ ~30 Hz wall-clock.
**Note**: Original spec called for AgiBot Alpha; pivoted to Beta because
allenwu06's HF token is approved for Beta but not Alpha. Schemas are nominally
identical per upstream README, but the on-disk schema differs from the sim
DigitalWorld sample previously pinned in `docs/schema-agibot.md` — the
"DigitalWorld" name in `schema-agibot.md` was already a tell that v0.1.0 was
trained on a sim/twin variant rather than real-robot capture.

Ground-truth files used (downloaded by B.alpha-hunter):
- `data/agibot_beta_sample/675/936938/proprio_stats.h5` — 1.17 MB, 1090
  frames. Note the filename: **`proprio_stats.h5`** (no second `s`), where
  v0.1.0 hard-codes **`proprio_states.h5`** everywhere.
- `data/agibot_beta_sample/task_info_675.json` — 417 KB, **a JSON list of
  399 episode dicts** (not a single-episode dict like the sim sample's
  `task_info.json`).

The on-disk Beta dataset layout is also different from sim DigitalWorld:

```
data/agibot_beta_sample/
  task_info_675.json                 <-- per-task, NOT per-episode
  675/                               <-- task_id at top level (no meta_info/ wrapper)
    936938/
      proprio_stats.h5               <-- single H5 here; no observations/ sibling at all
```

vs sim:

```
data/agibot_sample/
  meta_info/<task>/<uuid>/
    proprio_states.h5                <-- "states" plural
    task_info.json                   <-- single-episode dict
  observations/<task>/<uuid>/
    video/{head,hand_left,...}.mp4
    depth/<frame_idx>/{...}.png
  parameter.json
```

The sim layout assumed by v0.1.0 (`meta_info/` + `observations/` parallel
trees, single-episode `task_info.json`, joint `name` attrs, 34-joint state)
**does not exist in real Beta**. Conversion fails at multiple layers.

PASS is **misleading**:
- `timestamp monotonicity` only checks `np.all(np.diff > 0)`. It does NOT
  detect that Beta `/timestamp` is `int64` ns Unix epoch (~1.74e18) rather

  the unit is broken.
- `action-dim consistency` reports `dim=14` matter-of-factly; sim gave
  `dim=34`. The check is fundamentally raw-shape so it passes either way,
  but downstream forward conversion will not.

## 2. Schema deltas — Beta vs sim DigitalWorld

`docs/schema-agibot.md` describes a sim DigitalWorld sample (1 episode of
375 frames, 60 Hz claimed timestamp / 30 fps actual video). Beta is a
real-robot capture (1090 frames, ~30 Hz wall-clock). Deltas:

| Field / Group                          | sim DigitalWorld (`docs/schema-agibot.md`)                  | Beta (this sample)                                        | Severity                                  |
|----------------------------------------|-------------------------------------------------------------|-----------------------------------------------------------|-------------------------------------------|
| File name                              | `proprio_states.h5` (per v0.1 code; sim disk: same)         | `proprio_stats.h5`                                        | BLOCKER — detector fails before any logic |
| `task_info.json` shape                 | single dict, one episode per dir                            | one file `task_info_<task_id>.json` per task, list of all 399 episode dicts | BLOCKER for converter                     |
| Top-level dataset layout               | `meta_info/<task>/<uuid>/...` + `observations/<task>/<uuid>/` | `<task_id>/<episode_id>/proprio_stats.h5` only            | BLOCKER for converter                     |
| Sibling videos                         | `observations/<task>/<uuid>/video/{head,hand_left,...}.mp4` | none in this sample download                              | converter requires head.mp4 to exist      |
| `/timestamp` dtype + unit              | `float32` seconds (sim time)                                | `int64` ns Unix epoch (e.g. 1740109484562531000)          | HIGH — corrupts implied-rate WARN message |
| `/timestamp` rate                      | uniform 60 Hz claimed (16.67 ms)                            | ~30 Hz with jitter (33358–33360 ns) plus dropped frames (66682 ns gaps) | HIGH — strict-mono passes, drops invisible|
| File-level / group attrs               | `name` (34,) on `state/joint`, `action/joint`; `name`, `category` on effector; `name` on end, robot | **all groups have empty attrs `{}`**                      | BLOCKER — `attrs["name"]` raises KeyError |
| `state/joint/position` shape           | `(N, 34)` float32                                           | `(N, 14)` float64                                         | BLOCKER — JOINT_22 subselect impossible   |
| `state/joint/current_value`            | `(0,)` empty placeholder                                    | `(N, 14)` float64 populated                               | informational (richer in Beta)            |
| `state/joint/{velocity,effort}`        | `(N, 34)` populated                                         | `(0,)` empty placeholder                                  | informational (sparser in Beta)           |
| state subgroups                        | `effector`, `end`, `joint`, `robot`                         | + `head`, `waist` (each with `position (N,2)` populated)  | HIGH — converter ignores these joints     |
| `state/end/wrench`                     | `(0,)` empty                                                | `(N, 12)` float64 populated (force+torque, both arms)     | informational (richer in Beta)            |
| `state/effector/index`                 | `(N,)` float32 (frame counter)                              | absent                                                    | informational                             |
| `action/effector/index`                | `(N,)` float32                                              | `(N,)` int64                                              | informational (dtype change)              |
| `action/joint/index`                   | absent                                                      | `(1046,)` int64 — sparse control-source index, **length ≠ 1090** | HIGH — no LeRobot v3 slot                 |
| `action/end/index`                     | absent                                                      | `(1046,)` int64                                           | HIGH — same                               |
| `action/head/*`                        | absent                                                      | `head/index (N,) int64`, `head/position (N,2) float64`    | HIGH — new control surface, no v3 mapping |
| `action/waist/*`                       | absent                                                      | `waist/index (N,) int64`, `waist/position (N,2) float64`  | HIGH — same                               |
| `action/robot/orientation,position`    | `(N, 4)`, `(N, 3)` populated                                | `(0,)` empty                                              | informational (sparser in Beta)           |
| `action/robot/velocity`                | `(N,)` float32 (1-D, all zero in sim)                       | `(N, 2)` float64 (matches upstream README spec `[v_x, yaw_rate]`) | informational — Beta is the well-formed one |
| `action/robot/index`                   | absent                                                      | `(N,)` int64                                              | informational                             |
| dtype convention overall               | mostly `float32`                                            | mostly `float64` for populated arrays                     | informational — converter casts to f32 anyway |
| `parameter.json`                       | present, intrinsics + extrinsics for 8 cameras              | absent in this download                                   | informational (download didn't fetch it)  |

Summary of new-in-Beta surface area: 6 new datasets (`head/{index,position}`,
`waist/{index,position}` × {state, action} for the per-axis ones, plus
`action/joint/index`, `action/end/index`, `action/robot/index`,
`state/joint/current_value` populated). Plus the Unix-epoch ns timestamp
contract.

## 3. v0.1.1 candidate bug list (for B.5 to triage)

Severity uses the v0.1.0 spec definitions: BLOCKER = converter cannot
produce any output; HIGH = silent miscompile or misleading PASS; LOW =
cosmetic/observability.

1. **[BLOCKER, real bug] Filename hardcode `proprio_states.h5`.** Six call
   sites under `src/`: `preview/__init__.py:24`,
   `validate/__init__.py:20,22,51`, `validate/_report.py:86`,
   `convert/agibot_to_lerobot.py:298,693`, plus `lerobot_to_agibot.py:109`.
   Beta upstream uses `proprio_stats.h5` (no second `s`). Note
   `docs/schema-agibot.md` itself flags this exact misspelling at the top:
   "upstream README at `README:259` calls it `proprio_stats.h5` … Both
   names are wrong for the sample as released." v0.1.0 picked the wrong
   one for the released Beta data. Fix by accepting both names (or
   matching glob `proprio_stat[se]*.h5`).

2. **[BLOCKER, real bug] `state/joint.attrs["name"]` assumed present at
   `convert/agibot_to_lerobot.py:718`.** Beta has empty attrs everywhere.
   Raises raw `KeyError` (not the structured error type) — also breaks
   the error-reporting contract advertised in `cli.py`. Fix: detect
   missing `name` attr and either (a) infer from `state/joint/position`
   shape + a Beta-specific 14-name table, or (b) FAIL with a clear
   "real-robot capture detected; v0.1 supports sim DigitalWorld only"
   error.

3. **[BLOCKER, real bug] 14-joint subselect to 22 is impossible.**
   `JOINT_22` (head + body + arm + effector) does not exist in Beta —
   the 14 joints are likely 7-DoF arm × 2 (no head/body/effector in
   `/state/joint/`; head/waist/effector are separate groups in Beta).
   Forward converter would need a Beta-specific 14→14 (or 14+2+2+2 =
   20) join across `state/joint`, `state/head`, `state/waist`,
   `state/effector` to produce a usable observation vector. v0.1 cannot
   target Beta without this redesign. **Recommend punting Beta from v0.1
   scope and shipping v0.1.1 with explicit "sim DigitalWorld only" guard
   + clear error.**

4. **[BLOCKER, real bug] `_read_task_name` assumes single-episode dict.**
   `convert/agibot_to_lerobot.py:738-741` does
   `json.load(f).get("task_name", "unknown")`. Beta `task_info_*.json` is
   a list of 399 dicts. Would raise `AttributeError: 'list' object has
   no attribute 'get'`. Same bug in `preview/agibot.py:46-54` but there
   it's caught by `try/except` and silently returns `None` → "(unknown)".

5. **[HIGH, real bug] `/timestamp` dtype + unit.** v0.1.0 assumes
   `float32` seconds; Beta is `int64` ns Unix epoch. Validate's
   `implied_rate = 1/mean(diff)` would compute ~3e-8 Hz against a 30 fps
   video → confusing WARN message. Fix: detect dtype, divide ns→s if
   `dtype.kind == 'i'` and `magnitude > 1e15` (epoch-ns heuristic).

6. **[HIGH, real bug] preview reports `State dim: 22 (raw 14)` even when
   subselect is impossible.** `preview/agibot.py:115-116` always claims 22.
   Should report `raw_state_dim` directly when the schema is
   incompatible, or cross-check that JOINT_22 names exist in
   `state/joint.attrs["name"]` and report mismatch.

7. **[HIGH, real bug] preview hardcodes `robot_type: a2d`.** Should read
   from somewhere or report `unknown`.

8. **[HIGH, real bug] preview silently swallows task_info type mismatch.**
   List-of-episodes JSON returns `None` → `"(unknown)"`. Should detect
   list shape and either index into matching `episode_id` (file name has
   the task_id; episode_id is the dir name) or report the shape mismatch.

9. **[HIGH, schema gap] No mapping for `head`/`waist`/`*/index` arrays.**
   These are Beta-only control surfaces. v0.1.1 should at minimum decide:
   silently drop with a WARN, OR refuse to convert. Currently the
   converter doesn't know they exist.

10. **[HIGH, schema gap] No mapping for variable-length `index`
    companions.** `action/joint/index` is `(1046,)` while frames are
    1090. This is sparse-control bookkeeping (which frames came from
    teleop vs replay). LeRobot v3 has no slot. Document explicitly that
    v0.1 drops these.

11. **[HIGH, real bug] `validate` missing dataset-existence checks.**
    Beta sample has no videos at all; `frame-video alignment` and
    `fps consistency` SKIP rather than FAIL. When the user asked
    "is this dataset convertible?", PASS is the wrong answer. Suggest
    promoting "no videos found" to FAIL when `--strict` is set, or
    a new "schema completeness" check.

12. **[LOW, real bug] convert error path leaks raw Rich traceback** for
    `KeyError` on missing attrs. The structured `emit_error` wrapper at
    `convert/__init__.py:170` only catches `FileNotFoundError`. Should
    also catch `KeyError` / `ValueError` from H5 reads and produce a
    structured error with hint like "v0.1 supports AgiBot sim
    DigitalWorld; for Beta/Alpha real-robot data see roadmap."

13. **[LOW, real bug] convert `--from agibot` on a single-episode dir
    not containing `/meta_info/` fails with the wrong hint.** It says
    "AgiBot expects parallel meta_info/ and observations/" which is
    accurate for sim but is a layout requirement, not an inherent
    AgiBot requirement (Beta uses a flatter layout). Suggestion text
    should distinguish.

14. **[LOW, observability]** `inspect` doesn't surface attrs at all (it
    walks groups/datasets but ignores `.attrs`). Adding a one-line
    per-attrs summary would have flagged the missing `name` attr
    immediately. Cheap diagnostic.

15. **[LOW, schema-doc bug, not code]** `docs/schema-agibot.md` claims
    "60 Hz" for sim `/timestamp` but the official converter uses 30 fps
    everywhere (and the implied 60 Hz contradicts the 30 fps mp4s the
